一次面向团队的 AIGC 能力分享记录。用 RunningHub 完成主题视频生成 + 后期剪辑、字幕、配音全链路演示，最终交付至少 1 分钟的完整片段。脱敏整理。

## 演示目标

用 RunningHub 生成不同场景视频后，再进行后期剪辑、配字幕、配音。主题选定为某区域发展工程的环两江宣传。

## 技术路线

- **图生视频技术** — AI 制作分段图片 → 分段图片通过 AI 生成视频 → 剪映拼接合成
- **图片编辑技术** — Flux Z-image / Qwen-edit 等
- **首尾帧技术** — 准备好首帧、尾帧让模型自动生成中间过程，一致性较好但生成需要 10–30 分钟
- **混合策略** — 图片编辑 + 视频模型结合，闭源 + 开源模型混合使用

## 实现方案

- **云端服务** — 云端算力平台统一管理
- **开源生图模型** — 阿里 Z-Image
- **开源视频模型** — LTX 图生视频模型

## Prompt 工程

三个关键环节：

1. **图片反推** — 把参考图片交给 LLM 反推提示词
2. **LLM 反问** — 让 LLM 扮演 AIGC 提示词大师，并作为"最严格最刁难的卡梅隆式项目总监"不断对脚本反问，直到脚本足够成熟
3. **模板参考** — 给出主题（如"某地文旅"），分镜时长 5–8 秒，成片长度 1 分半，参考既有视频脚本格式生成新主题脚本
4. **上下文参考尽量丰富** — 给 LLM 提供"镜号 / 旁白文案（带标点停顿）/ 首帧 Text-to-Image prompt / 图生视频 Image-to-Video prompt / 是否一镜到底+慢动作 / 参考图片"列表，让它一次性理解完整结构

## 工作流关键决策

- 分段生成优于整段生成 — 每段独立可控
- 上下文模板越完整，LLM 输出越稳定
- 首尾帧一致性高但耗时长，需在效率与一致之间权衡
